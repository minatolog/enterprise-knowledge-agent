## 背景与问题

制度初始化时已经发现用户编写的 `docs/enterprise_rag_architecture_development_guide.md`，但只将其称为“架构指导”。用户随后明确要求“整个开发要用这个文档作为总指挥”。需要避免新 AI 流程文件被误认为替代技术路线。

## 候选方案

| 方案 | 收益 | 代价/风险 | 依据 |
|---|---|---|---|
| AI 制度同时决定技术路线 | 只有一个入口 | 容易覆盖用户的总架构 | 与用户补充指令冲突 |
| 总架构指导管技术方向，AI 制度管记录和追溯 | 保留用户原方案，职责清晰 | 每次任务须读两份文档并核对当前代码 | 用户明确指定，且指导本身要求核实代码现状 |

## 选择与原因

采用第二种：开发阶段、目标架构与技术约束先对照总指导；Prompt、日志、Task ID 与 Git 留痕按 `docs/ai_workflow/`。当前代码仍是已实现事实，不因指导中列出 FastAPI、Docker 等目标就宣称这些能力已完成。若未来任务明确偏离指导，记录原因和新指令；不静默改写用户原文件。

## 风险与重新评估条件

总指导目前未被 Git 跟踪；若只提交制度文件，GitHub 上的链接会缺失。用户审查时需决定是否把该原文件一并提交。若指导后来更新，应保留版本差异，并在相关任务中说明影响。本次未修改指导原文、未 Commit 或打 Tag。
