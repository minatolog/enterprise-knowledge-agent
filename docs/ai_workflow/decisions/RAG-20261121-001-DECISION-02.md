# RAG-20261121-001-DECISION-02 — 企业链路核验失败不再返回 502

- 决策日期：2026-11-21 / Australia/Sydney
- 状态：提议
- 关联任务：[RAG-20261121-001](../execution_logs/RAG-20261121-001.md)

## 背景与问题

原 `Runtime._query`：引用编号无效或 LLM 判官判否时抛 `HTTPException(502)`，用户得不到任何内容，前端无法区分“服务故障”和“回答不可信”。判官只给整段 true/false。

## 候选方案

| 方案 | 收益 | 代价/风险 |
|---|---|---|
| A 保持 502 | 不改契约 | 体验差；一句不被支持就整段丢弃 |
| B 200 + `verification` 状态；逐句核验，删除不被支持的句子 | 保留可信部分并明确标注；前端可展示 | 改变 API 语义（原测试断言 502）；判官仍可能误判 |

## 选择与原因

采用 B。`verification` 取值：`judge_passed`、`judge_partial`（删除不被支持的句子并在末尾注明，`unsupported_claims` 列出被删句子）、`judge_failed` / `citation_invalid`（回答被替换为拦截说明，`sources` 为空，`status=refused`）、`citation_structure_only`、`refused`。非 `passed` 结果不写缓存。判官仍兼容旧的 `{"supported": bool}` 输出；任何格式错误按“不支持”处理（fail-closed）。

## 风险与重新评估条件

判官为同一模型，存在相关误差；`judge_partial` 的删句依赖字符串匹配。若出现误删或漏删，应补人工抽检样本后再调整。
