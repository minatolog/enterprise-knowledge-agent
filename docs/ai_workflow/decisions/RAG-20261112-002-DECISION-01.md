# RAG-20261112-002-DECISION-01：局部接入 LangChain 与 LangGraph

- 日期：2026-11-12；状态：已实施，待用户审阅。
- 用户指令：[Prompt](../prompts/implementation/RAG-20261112-002_langchain_langgraph.md)。
- 背景：原系统由 RAGService 手工顺序编排，未使用 LangChain/LangGraph。总架构指导将 LangGraph 列为 P2，本次用户明确要求使用这两项技术，因此实施局部扩展，不修改总指导、不追溯改写旧验收。

## 选择与替代

采用 `langchain-core` 的 BaseRetriever、Document、RunnableLambda 适配现有检索和生成；用 LangGraph StateGraph 显式编排索引检查、检索、上下文、生成、引用映射和无证据分支。CLI/API 的 RAGService 默认实际执行 compiled graph。

替代方案：继续手写编排；直接重写为 LangChain 内置 Agent；更换向量存储适配器。选择局部接口适配，保留已验证的 Dense/BM25/RRF/Reranker、DeepSeek Responses 协议及自定义人设 Prompt，避免算法、模型和框架同时迁移。

直接依赖固定为 langchain-core 1.8.0、langgraph 1.2.20；新增传递依赖一并锁定。langchain-core 要求 certifi>=2026.10.19，因此将原 requirements 的 certifi 2026.7.22 更新为当前项目环境已有的 2026.10.23。新增成本是框架及传递依赖升级兼容维护；顶层 langchain Agent 包不在本次使用范围。

## 数据与能力边界

- Document 保留 chunk_id、页码、来源、所有检索评分；无索引重建，无原始资料或评测数据改动。
- graph 每次 invoke 使用独立状态，不配置 checkpointer/store，不增加跨请求记忆。
- 无证据走明确分支并跳过 LLM；现有异常和引用契约保持。
- 不增加 Agent、自主工具调用、人工审批、流式接口或 LangSmith 云跟踪配置。langsmith 是框架传递依赖，安装不等于启用云服务；部署方应审核自身 tracing 环境配置。
- 重新评估条件：需要可恢复长任务、人审、会话记忆、多步骤工具调用或框架版本升级时。
