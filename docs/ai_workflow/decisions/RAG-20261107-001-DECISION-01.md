# RAG-20261107-001-DECISION-01 — 使用仓库内 Task ID 与双向链接追溯 AI 开发

- 决策日期：2026-11-07（澳大利亚悉尼）
- 状态：已作为本次制度草案实施，待用户验收
- 关联任务：[RAG-20261107-001](../execution_logs/RAG-20261107-001.md)

## 背景与问题

现有代码、DevLog 和报告记录了技术过程，但没有完整 Prompt 与执行结果的一对一入口。不同 AI 工具不能共享完整聊天历史，历史 Prompt 也无法从 Git Commit 可靠推断。

## 候选方案

| 方案 | 收益 | 代价/风险 | 判断依据 |
|---|---|---|---|
| 只依赖 AI 聊天历史 | 不新增仓库文档 | 跨工具不可见、与代码版本脱节 | 当前仓库缺 Prompt 归档 |
| 每次任务保存 Prompt/执行记录，统一 Task ID，并在 Commit 中标记 | 可从代码、任务、决策双向追溯；纯 Markdown 易维护 | 需要每次归档并在提交后回填 SHA | 本次任务要求，且无需新依赖 |
| 引入专门项目管理服务 | 可做高级查询与提醒 | 增加外部账号、同步及维护成本 | 当前单仓库规模尚不需要 |

## 选择与原因

采用第二种方案：`RAG-YYYYMMDD-NNN` 统一标识，`TASK_INDEX.md` 作入口，原始 Prompt 与每次执行分开保存，Commit 标题含 Task ID。Git SHA 在提交后追加回填，避免要求文件记录自身的 Commit SHA。现有文档只链接，不搬迁或重写。

## 风险与重新评估条件

人或 AI 可能忘记归档；因此根目录 `AGENTS.md` 与模板同时提示执行顺序。敏感 Prompt 不得原文入库，须标明脱敏范围。若任务量明显增加、多人同时分配 ID 发生冲突，再评估自动编号或外部追踪工具。本次不创建 Commit/Tag，正式启用仍待用户验收。
