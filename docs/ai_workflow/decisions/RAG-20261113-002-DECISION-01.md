# RAG-20261113-002：企业能力作为隔离扩展交付

日期 2026-11-13；状态已实施待审阅。[用户完整指令](../prompts/implementation/RAG-20261113-002_enterprise_completion.md)。

用户授权完成既有图中红色能力，未指定现有企业平台，并要求完成后更新图。总指导原将 ACL/连接器等列为 P2，本次明确扩展任务优先级，不静默修改原指导。

采用独立 app.enterprise API /api/v2 和独立 .enterprise 数据目录。旧 app.api、现有工作流页面、正式 CNOOC 文件、索引、白名单、原评测保持。核心问答复用已有 LangChain/LangGraph RAGService，企业检索分支复用 Dense/BM25/RRF/CrossEncoder 技术和模型，增加授权候选约束；不是替换原有 P0 检索评测口径。

SQLAlchemy 提供 SQLite 本地后端和 PostgreSQL 真正适配；对象为内容寻址本地存储/S3；缓存为有界本地缓存/Redis；任务为显式开发 eager 模式/Celery-RabbitMQ；JWT 验证 OIDC RS256（issuer/audience/JWKS）与明确标识的本地 HS256；不提供默认固定口令。正式身份供应商的授权码登录流程由企业 SSO 集成侧负责，本项目验证访问 Token。

索引按租户创建不可变 Chroma Collection，全部构建验证后在 SQL 中原子切换指针；共享目录的 FileLock 串行化写入。读侧每次取发布版本和即时 ACL，两路检索在授权文档集合内进行。回滚不恢复已撤销权限。文件原文按指定 release 返回对应版本并再次鉴权。缓存/历史按用户、权限、版本隔离。多主机需要共享存储或替换锁服务，本次不宣称分布式 HA。

上下文用 tiktoken 限额与去重，版本在快照中固定；额外 LLM judge 默认启用，结构校验确定性执行，语义检查失败或异常不发布回答。但判别器质量仍需真实评测及人审，不能把代码接入等同于准确率验证。每个有证据回答默认增加一次模型核验调用。

依赖：在 requirements-enterprise.txt 中单独固定 SQLAlchemy/psycopg、Celery、boto3、Redis、PyJWT/cryptography、Prometheus、tiktoken、multipart 及新增传递依赖；requirements-ocr.txt 按需安装 Docling，避免旧环境默认负担。新维护成本是适配、模型解析资源、数据迁移和安全回归。没有替换原 requirements 固定版本。

对象服务最初尝试 MinIO 两个仓库失败，改用 SeaweedFS 4.53（S3 协议不变），记录在 [ISSUE-01](../issues/RAG-20261113-002-ISSUE-01.md)。PostgreSQL/Redis/RabbitMQ 真正服务已验证；容器后续启动、外部身份/OA、生产压测、生成质量明确保持待验收，不把配置或模拟测试标成生产完成。
