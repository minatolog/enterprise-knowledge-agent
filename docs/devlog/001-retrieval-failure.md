# DevLog #001 — RAG 语义检索不稳定与错误拒答问题

**日期：** 2026-10-18  
**项目：** Enterprise Knowledge Agent  
**模块：** Retrieval / Chroma / Embedding / RAG  
**状态：** 问题已复现，优化方案待实现

## 1. 问题背景

当前系统使用以下技术实现企业知识库问答：

- Embedding：BAAI/bge-small-zh-v1.5
- Vector Database：Chroma
- Retrieval：Top-K Semantic Search
- LLM：DeepSeek
- Guardrail：基于向量距离的阈值过滤（0.9）

在测试企业密码安全制度时，发现用户使用不同的自然语言表达询问同一业务规则，系统返回的检索结果差异较大。

## 2. 问题复现

| 用户问题 | Distance | 检索结果 |
|---|---:|---|
| 输错十次密码之后要怎么办？ | 1.1235 | 超过阈值，系统拒答 |
| 输入十次错误密码 | 0.7781 | 错误匹配 IT 密码安全章节 |
| 输错多少次密码会被锁定？锁多久？ | 0.8381 | 正确匹配安全制度 |

观察发现：

1. 语义相近的问题可能产生明显不同的检索距离。
2. 固定距离阈值可能导致存在答案的问题被拒答。
3. 多份文档包含相似关键词时，可能发生检索偏移。
4. 即使找到相关文档，生成答案仍可能存在数字错误或表达不规范的问题。

## 3. 初步原因分析

**问题 A：向量检索存在表达敏感性**

Embedding 模型将自然语言转换为向量，但不同问句的向量位置并不完全一致，因此语义相近的问题也可能获得不同排序。

**问题 B：固定检索阈值存在局限**

目前根据少量样例设置 MAX_DISTANCE = 0.9，缺乏系统性评测，可能产生 False Rejection。

**问题 C：不同文档存在语义竞争**

IT 密码安全政策和账号锁定制度都包含密码相关信息，纯向量检索有时不能正确区分业务意图。

## 4. 拟采用的解决方案

### 方案一：建立 Retrieval Evaluation Dataset

构建包含不同问法、标准来源与预期答案的测试集，计算：

- Recall@K
- Hit Rate@K
- MRR
- 无答案问题拒答准确率

### 方案二：Hybrid Search

结合 BM25 关键词检索和向量检索，利用 Reciprocal Rank Fusion（RRF）融合候选结果。

### 方案三：Reranker

使用 Cross-Encoder 对候选 Chunk 进行重新排序，提高相关文档进入最终上下文的概率。

### 方案四：Grounded Answer Evaluation

检查生成答案是否忠实于检索证据，重点测试数字、条件、时间、金额等敏感信息。

## 6. 当前结论

当前问题表明：端到端 RAG 功能跑通不代表检索质量已经达到生产要求。

下一步将采用可复现测试集与量化指标驱动检索优化，而不是单纯依靠人工提问观察结果。

### 实验更新：Vector-only 与 Hybrid Search 对照

**日期：2026-10-19**

在相同的 6 条有标准来源的问题上，对 Vector-only 与 BM25 + Vector + RRF Hybrid Search 进行排序评测（未应用距离阈值）。

| 指标 | Vector-only | Hybrid |
|---|---:|---:|
| Hit@1 | 83.33% | 83.33% |
| Hit@3 | 100% | 100% |
| MRR@3 | 0.9167 | 0.9167 |

**实验发现：**

Hybrid Search 已成功实现，但在当前小型测试集上没有提升检索排名。针对“输错十次密码之后账号会怎么样？”这一问题，两种方案都将正确安全制度排在第二名。

**下一步：**

引入 Cross-Encoder Reranker 对召回候选文档重新排序，并在相同评测集上进行三方案对照。

*以上结果仅代表当前小规模数据集的测试表现，尚不能推断真实企业环境中的泛化效果。*
